# 本机技能分工

本 Skill 是已有关键帧的动效设计入口，依次解决画面依据、动作机制、运动质感、项目差异和执行表达。以下是本机已读技能的按阶段分工，不是程序自动调用链，也不意味着默认同时加载全部正文。

## 直接复用

| 阶段 | Skill | 使用范围 |
|---|---|---|
| 视觉前置与验收 | visual-task-gate、warriors-work-principles | 区分内容与参考，先有设计依据再执行，实际输出才可验收；已有项目背景不重复询问 |
| 看实际图片/视频 | vision-tools | 识别结构与反馈；MCP 不可用就使用现有视觉工具，不宣称未读取内容 |
| 编译已选动作 | jimeng-prompt-reference-skill | 当前模式的素材职责、动作/镜头/时间、全局保持与冲突检查；不重新替换已选创意 |
| 准确文字 | ai-video-text-safe-workflow | 仅相关路线、风险和保持项；承接用户带字生成/后期拼贴决定 |

## 设计知识提炼

`video-motion-graphics` 的 12 条动画原则，经 [运动设计](motion-design.md) 转为适合即梦的可观察动作。默认直接读这份提炼，不每段加载 AE 表达式、帧数表和整套工具说明。用户明确要求 AE 操作再读原技能。

`svg-animations` 提供路径依附、分组与局部运动分离、遮罩显隐、前动作结束触发后动作等设计思想。这里只迁移设计关系，不迁移 SVG 命令、同点数形变条件或代码控制精度。

缓动/周期、注意力与错峰等在 slack-gif-creator、frontend-design、ui-ux-pro-max 中有重复，主来源已覆盖，不复制多套。Remotion/渲染、Slack GIF、网页交互、社交视频脚本仅在用户选择该输出或任务时路由；不改当前即梦工具链。

## 处理边界与冲突

1. **内容与运动分别规定。** 字形内容准确不意味着整体位置固定；用户许可标题平移、模块沿轨道运动时，明确内容不变、允许变换和终态。若本段要求文字静止，才固定相关图层/载体。
2. **已有输入优先。** 普通单图/多帧提示词任务不执行文字 Skill 中的双版本生图或修帧制作步骤，不要求补帧。用户提出实际图片任务时才按默认图片 Plugin 另行执行。
3. **用户明确设计优先。** 既定匀速、无回弹、固定机位、标题整体入场等不能被一般动画建议改写。专业原则只能完善未指定部分。
4. **条件原则不是平台保证。** “永不线性”、120%～150% 回弹、固定 2～4 帧预备等是传统工具中的局部建议，不复制为即梦硬要求。路径指令、时间戳与空间关系是期望，不具有确定性几何/逐秒锁定精度。
5. **设计提案就是本任务产物。** 只要提示词则只给成品，用户已选方向不再请求批准；授权实际视频生成时才执行生成与验收，不擅自增加付费/上传任务。
6. **资料按需。** 普通片段先依据图片及本地精选参考，库不足才联网；需要 Pinterest 静态图参考时遵循 pinterest-reference-design。图片灵感不等于运动验证。
7. **输入角色约束初态。** 严格首帧与一般视觉参考不同。完整标题已在严格首帧中，不能同时指定片头无标题后再入场。说明冲突，优先基于已有图提出短暂移出后回入、原位效果揭示等最小替代，须明确这是调整建议；用户坚持原入场且模式限制无法满足时再指出所缺输入，不默认生成额外图。

旧技能未在安装时被改写。上述提炼保留明确来源，后续原技能变化时按实际差异更新；不靠全量合并维持“一切都涵盖”的假象。
