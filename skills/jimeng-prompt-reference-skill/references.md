# 即梦提示词参考 Skill：Reference Notes

这些是编写 `jimeng-prompt-reference-skill` 时实际查阅过的资料和可迁移结论，不是平台官方规则的替代品。

## Runway Academy Prompting Guide

来源：[Prompting Guide](https://academy.runwayml.com/guides/prompting-guide)

可迁移结论：

- 图生视频中，输入图负责构图、主体、光线和风格；文字重点描述运动、镜头和时间顺序。
- 从简单提示词开始，一次增加一个变量，便于判断哪个修改产生了结果。
- 避免互相冲突的指令；过度复杂的长提示词可能导致模型难以同时遵守。
- 使用具体、可观察的描述，例如锁定机位、最小主体运动、连续镜头。

平台边界：以上是 Runway 的公开指南，只作为跨平台原则，不能证明即梦会完全按相同方式执行。

## RunComfy AI Video Generation / Seedance Skill

来源：[AI Video Generation](https://skills.sh/prime-skills/runcomfy-agent-skills/ai-video-generation)、[Seedance v2](https://skills.sh/prime-skills/runcomfy-agent-skills/seedance-v2)

可迁移结论：

- 当参考图已经清楚提供身份、服装和品牌细节时，优先让参考图承担这些静态内容，提示词描述变化中的动作和镜头；如果任务要改变静态内容，要明确写出改变对象和方向。
- 多模态或多参考输入要明确“哪一张参考负责什么”，并使用目标平台实际支持的素材标识。
- 短视频或单个时间段先确定一条主要动作主线；多个动作可以按时间顺序组合，避免无范围地堆叠形容词和动作。
- 参考素材和输出画幅应尽量一致，避免平台自动裁切造成位置漂移。

明确不迁移：RunComfy 的接口、模型路由、参考图数量、时长范围、分辨率、参数名和登录流程。它们只对对应 RunComfy 模型有效。

## Local image-generation guidance

本地 `baoyu-image-gen` 和 `codex-image2` 的可迁移原则：

- 参考图要少而明确，身份参考不应被长篇虚构的脸部描述覆盖。
- 编辑任务要明确“只改变什么”和“保持什么”，避免模型重做整张图。
- 图片生成要检查实际文件、尺寸、主体、构图和边缘；提示词本身不是交付结果。

平台边界：这些 Skill 面向图片生成 API，不自动提供即梦视频的专用规范。

## Square-Zero-Labs/video-prompting-skill

来源标识：`Square-Zero-Labs/video-prompting-skill@video-prompting`，2026-08-27 检索。

可迁移结论：

- 先区分模型和生成模式，再选择对应的 prompt reference；不要把一个模型的模板当成所有模型的规范。
- 图像负责身份、服装、构图等静态事实；提示词主要描述动作、镜头、时间和变化。
- 首尾帧、首帧到视频、尾帧到视频、多帧参考和多参考图是不同输入协议，应分别描述。
- 多模态输入要明确每张参考图的作用和优先级，冲突时说明取舍。

明确不迁移：RunComfy／Seedance／其他模型的接口字段、模型名、权重语法、参考图数量、分辨率、时长上限、费用、登录流程和 Alpha 能力。该 Skill 的安装量、更新时间或仓库热度也不能证明其适用于即梦。

## Chroma-key and Alpha boundary

来源：OBS `Chroma Key Filter` 公开文档。

可迁移结论：绿幕抠像需要处理色度范围、边缘和绿色溢出（spill）；这属于后期抠像与导出链路，不是提示词可以单独保证的 Alpha 通道。生成提示词只负责尽量提供均匀纯色背景、避免阴影和背景变化。

## Empirical prompt iteration note

本 Skill 的“最小基线”不是“最短提示词”。当用户已经通过生成结果验证了某些约束有效时，后续优化必须保留这些约束，只修改导致新失败的变量。对于首尾帧数字人视频，用户实测中可能出现：删除胸腹和肩膀锁定后重新呼吸；加入“轻微微笑”后出现嘴角抽动、挑眉或其他面部表演。因此应把“保持参考图原有表情不变”和“生成轻微微笑”分成两个互斥目标，不能为了压缩字数而混合或删除已验证约束。

## Case study only: seven-video naturalness finding

以下是一次特定的七段首尾帧数字人对照测试，仅供“同类任务且出现同类失败”时参考，不是所有视频或图片提示词的默认规则。除非当前任务明确匹配，不要复制其中的时间段、人物部位、绿幕或面部限制。

该测试提供了以下实测规律：

- 1、2 的提示词允许“极轻微自然呼吸”，身体和轮廓仍会出现可见变化；“自然”没有解决衔接稳定性。
- 3、4、5 的提示词相同，均要求轻微微笑，但生成结果的身体变化和面部状态并不一致。这说明同一提示词的单次结果不能当作确定性因果，需保留随机性和 A/B 对照。
- 6 首次明确“只做画面外观形变、不产生身体动作”，同时又要求嘴角微笑；身体更稳定，但面部动作目标仍可能带来异常表情。
- 7 加入首尾帧时间分段，并完全取消面部表演后最接近目标；但“身体和各部位完全锁定”可能让过渡显得僵硬。

由此得到的优化顺序：先保留 7 的时间分段、姿态稳定、面部锁定和绿幕约束；只把“完全锁定”改为“姿态／位置稳定、无可见待机动作”，再补充外观形变的连续、柔和、无突跳。不要用呼吸、眨眼、微笑或“自然动作”修复僵硬。

## Reusable Jimeng prompt pattern extracted from the case

这组素材可以提炼出“同平台同模式”的提示词组织方式，但不能提炼出适用于所有任务的固定内容。

可迁移的结构：

- 先说明参考图或首尾帧的角色；
- 用短时间段说明何时保持、何时变化、何时稳定；
- 每个短视频或时间段先确定一条主要动作主线；多个动作按时间和对象分开描述，并用“对象＋变化＋幅度／速度”表达；
- 把身份、构图和不允许变化的部分单独列出；
- 负面词只保留本次任务已出现或明确需要规避的问题。

必须按任务替换的槽位：

- 主体：数字人、汽车、产品、风景等；
- 变化：轮廓形变、镜头推进、蒸汽上升、材质变化等；
- 保持项：人物姿态、产品位置、镜头构图或场景光线；
- 背景与输出：绿幕、普通场景、透明导出或其他后期要求。

因此，“即梦适配”指的是在同一模式下复用结构和表达粒度，不是把七段数字人的完整提示词当作万能模板。
