## 1. 基础提示词

官方给出的完整结构是：

```text
完整提示词
= 【素材描述】
+ 【一句话概述】
+ 【具体情节描述】
+ 【全局补充（结尾）】
```

### 1.1 素材描述

按上传顺序写出素材编号和具体用途。用途包括人物、音色、动作、场景等。没有参考图、参考视频或参考音频时，可以省略这一项。

要点：不要只写“参考图片”，要说明“哪个素材负责什么”。例如：`@图片1负责人物外观，@视频1负责动作和运镜，@音频1负责音色`。

### 1.2 一句话概述

```text
主体 + 地点 + 事件 + 题材／风格 + 特殊运镜
```

这一句负责让模型先获得全片的总体方向，不替代后面的分镜细节。

### 1.3 具体情节描述

可以按时间轴或故事线写。单个分镜／时间段包含两类信息：

```text
➕ 正向描述：画面具体内容 + 运镜 + 动作 + 台词 + 音效
➖ 反向描述：不需要的元素，例如“不要字幕”“不要 BGM”
```

正向描述写“画面实际要发生什么”；反向描述写“这一段或全片不要出现什么”。不能只写“自然、电影感、流畅”，而要落到画面、镜头、动作、对白和声音。

### 1.4 全局补充（必须放在结尾）

再次强调整个视频中都要具备的元素，以及贯穿始终的画面细节。例如：

```text
机位 + 环境／场景特征 + 整体声音／氛围 + 光影
```

字幕、BGM 等全片都不想出现的元素，也可以在这里再次强调。全局补充不是重复所有分镜，而是收束全片一致性。

此处“放在结尾”描述公式的收束顺序，不表示必须逐字保留章节标题、正负符号或把缺标题的自然段成稿判为错误；官方基础示例以连贯段落表达，反向内容按范围放入情节或全局补充。

### 1.5 官方基础示例体现的写法

官方示例把主体、环境、画面风格、镜头位置、参考素材作用、时间段动作、物理反馈、景深、声音和整体氛围连成一条完整提示词。例如主体动作会同时写到水面涟漪、光线穿雾、镜头跟随、环境音和主体回到稳定状态。这说明“动作”不仅是人物动词，也包括动作造成的环境反馈、声音和镜头响应。

## 2. 真人人物／动画人物描述

官方明确说明，这套人物公式除了真人，也可以用于动画人物。总体公式是：

```text
人物
= 【年龄／种族】
+ 【肤色／皮肤质感】
+ 【面部细节特征】
+ 【眼神／灵魂】
+ 【发型／发色】
+ 【服装／服装质感】
+ 【体型／情绪／气质】
+ 【其他要求（如有）】
```

### 2.1 年龄／种族：人物基调

写明具体年龄段、人种和脸型风格。

```text
【具体岁数】 + 【具体国籍／人种】 + 【风格形容词】 + 【脸型名词】
```

官方示例使用“22 岁东亚女性”“25 岁英国男性”“26 岁非裔黑人女性”等具体年龄和人种，再配合清冷古典骨相脸、英伦贵族脸、黑珍珠超模脸等基调。

### 2.2 肤色／皮肤质感：避免扁平白，增强真实感

写明色调和真实质感。

```text
【冷暖色调】 + 【具体肤色名词】 + 【皮肤质感形容词】
+ 【保真后缀：保留真实的微细毛孔与肌肤纹理】
```

可按人物需要增加雀斑、瑕疵、干纹、胡茬痕迹等真实细节。重点不是一味写“白皙”，而是指定色调、触感和真实纹理。

### 2.3 面部细节特征：决定辨识度

至少组合 3—4 个面部维度：

```text
【眼型描述】 + 【眉骨特征】 + 【鼻梁特征】
+ 【唇形特征】 + 【下颌线／骨相特征】
```

例如桃花眼、丹凤眼、杏眼，眉骨高低，鼻梁和鼻头，唇珠、唇部丰润程度，下颌线柔和或利落等。不要只写“美女”“帅哥”这种无法锁定辨识度的泛词。

### 2.4 眼神／灵魂：决定情感

```text
【眼神形容词】 + 【目光传达的信息／比喻】
+ 【透出的底层情绪】
```

眼神要说明“看向哪里、传达什么、底层情感是什么”，而不是只写“深情”“有灵气”。

### 2.5 发型／发色

明确发色、发型结构、固定方式、发丝状态和运动时的细节。例如长短、盘发或散发、发饰、碎发、光泽、风吹时的变化。发型描述属于身份一致性，发丝随风的变化属于时间中的动作，二者要分开写。

### 2.6 服装／服装质感：展现风格

写明具体款式、材质和新旧状态，从侧面烘托人物特性。

```text
【服装款式】 + 【材质／光泽／纹理】 + 【新旧或磨损状态】
+ 【关键配饰或结构】
```

官方示例包括真丝或轻纱的柔软光泽、皮夹克的磨损折痕与金属拉链反光、西装的羊毛混纺材质等。

### 2.7 体型／情绪／气质：决定构图与故事感

```text
【骨架／肩部特征】 + 【构图／镜头要求】
+ 【人物动作／视线】 + 【整体散发的氛围词】
```

如果整体故事提示词已经写了构图、镜头、动作和视线，可以去掉人物公式中的重复部分。也就是说，人物公式是模块，不是每次必须完整重复的长清单。

## 3. 30 秒长视频

官方说明：30 秒长视频可以结合时间戳、多模态参考、去除无关项等功能。官方推荐的模块化结构是：

```text
总述名称
+ 模块一：多模态参考层
+ 模块二：全局设定
+ 模块三：时间戳剧本分镜
+ 全局禁止与收束
```

官方示例说明，下面的长提示词是示例，实际可以根据公式写得更短；这里的模块不是要求每条短视频都全部使用。

### 3.1 总述名称

用一句话描述整个视频的基调，例如“29 秒一镜到底（古装女子江边告别）”。它是全片的定位，不是剧情细节。

### 3.2 模块一：多模态参考层

没有上传参考图、参考音频或参考视频时可以忽略。

```text
基于上传的【参考素材类型】，严格保持【需要一致的内容】一致，严格锁定【需要锁定的内容】。
```

官方示例：基于图片，保持 `@图1` 的人物面孔／特征一致，保持 `@图2` 的构图、白模或空间关系一致，严格锁定人物站位。官方还说明，全文中可以多次 `@图`、`@视频`、`@音频`，以提高对应关系的准确性。

### 3.3 模块二：全局设定（全局世界观＋防崩坏）

```text
【基础环境与质感】
+ 【视觉风格】
+ 【镜头语言】
+ 【人物造型／主体造型】
+ 【表演核心】
+ 【禁止项】
```

各项含义：

1. 基础环境与质感：`时间 + 地点 + 氛围 + 物理质感要求`。
2. 视觉风格：电影感、写实、二次元等 + 景深控制 + 打光方式。
3. 镜头语言：景别／视角 + 详细镜头运动或镜头节奏。
4. 人物造型：可以沿用本文件第 2 节，或直接引用参考图；非人物主体可以写 `数量词 + 颜色 + 外形／设计风格 + 具体物品名词 + 材质细节／磨损状态 + 标志性特征`。
5. 表演核心：成片中需要重点强调的内容，按实际任务填写。
6. 禁止项：从声音、字幕、行为和容易崩坏的地方等方面列出限制，例如禁止大幅度肢体动作、禁止多余台词或 BGM、禁止字幕。

### 3.4 模块三：时间戳剧本分镜

官方定义是：把长视频切成若干短时间切片，并写明每个切片必须严格遵守的内容，以便精准导戏。

每段时间切片公式：

```text
【开始秒数 - 结束秒数】 + 【核心阶段／主题】
【动作／表情等物理层面指令】：景别 + 构图 + 人物细节动作等
【情感解析或镜头调度等潜台词】：向 AI 解释物理指令的深层表达
【其他要求（按需）】：例如切镜、转场和声音
```

官方示例把每段分为“阶段名称、动作／表情、情感解析”，并用眼神、停顿、呼吸、唇部、眉心、眼泪等具体可观察细节承载情绪。这里的“潜台词”不是让模型生成字幕，而是解释动作要表达的情绪或叙事意图。

## 4. 超长视频

官方给出的超长视频组织方式是：

```text
全局参数
+ 素材描述
+ 一句话概述
+ 具体情节描述
+ 全局补充
```

官方示例会在开头写视频时长、画幅比例、画质和风格，再写故事主题、主角设定、核心视觉元素，之后用连续时间段推进完整剧情，最后统一写人物一致性、镜头流畅、物理逻辑、视觉元素和禁止项。

如果使用完整时间轴，时间段应覆盖目标时长，并保持人物、服装、发型、脸部、体型和核心视觉元素的连续性。禁止项可以覆盖变形、手部错误、重复人物、错误文字、字幕、Logo、水印、低清晰度、闪烁、突兀跳切和不连贯动作等当前任务真正担心的问题，不要无条件全部加入。

## 5. 视频延长与转场

### 5.1 视频延长

明确延长方向和接续关系：向前延长、向后延长、延长续写等。

官方示例结构：

```text
参考 @视频1 的内容，延长视频 N 秒，向后延长／延长续写。
+ 动作衔接要求
+ 禁止生硬切镜
+ 禁止物体凭空出现
+ 新片段的具体动作、人物、镜头和声音
```

可使用“延长自然、动作衔接流畅、动作衔接自然”等要求，但还必须写清楚原片尾接下来发生什么。若要转场，必须说明转场类型和切镜逻辑，例如遮罩转场：前一镜中的落叶遮挡镜头变暗，镜头穿过遮挡后显现下一场景，并说明前后景别关系。

### 5.2 创意转场

官方示例体现的完整逻辑是：

```text
转场类型指引
+ 基础约束要求
+ 切镜逻辑要求
```

转场不能只写“高级、丝滑”。需要描述转场前状态、触发物或遮挡物、转场过程、转场后状态，以及前后镜头如何衔接。必要时写“禁止生硬切镜”“禁止物体凭空出现”。

## 6. 智能编辑／高级编辑／视频编辑

### 6.1 常规编辑

官方说明：常规提示词应尽可能写出修改内容从 A 到 B、如何改变，并配合时间戳；同时支持额外输入图、视频和音频。

官方建议使用的动作词包括：

```text
编辑视频里的……
增加／加上……
删除／去掉……
修改／替换／改成……
```

公式：

```text
【具体修改对象／什么东西】
+ 【动作与变化描述】
+ 【生效时序】
```

例如：把男生的牛仔裤替换为深黑色西装裤；在视频 1—8 秒生效。未被要求修改的景别、运镜、人物、背景和声音应明确保持。

### 6.2 高级编辑／视频编辑的圈选与标记

相比智能编辑，高级编辑增加了标注工具与方位。完整公式是：

```text
【标注工具与方位】
+ 【具体修改对象／什么东西】
+ 【动作与变化描述】
+ 【生效时序】
```

1. 标注工具与方位：说明使用什么工具，以及 AI 关注工具里面还是外面。工具包括不同颜色的框、线、箭头、文字和地标点；示例表达为“红框内”“沿红色箭头指向的区域”“地标点处”“红线左侧”。
2. 具体修改对象：在标注区域内明确要改什么，例如男生的牛仔裤、背景的枯树、手里的咖啡杯、天空中的云层。
3. 动作与变化描述：明确变成什么、添加什么或消除什么，例如替换为黑色西装裤、变成盛开的樱花树、无痕消除并补全背景、增加一道闪电。
4. 生效时序：说明全片持续还是只在特定时间变化，例如全片统一、仅第 5—8 秒、从第 3 秒逐渐显现。该时序应配合界面生成的系统时间轴使用。

## 7. 白模

官方说明：白模支持粗颗粒度和细颗粒度；当前模型生成粗颗粒度效果通常更好。两种模式的参考重点和提示词公式不同，不能混写。

### 7.1 粗颗粒度

定义：用球体、圆柱、方块等简单几何体拼接表示人物、物体或动物的低保真 3D 模型视频。

重点参考：运动轨迹、运镜方式、角色站位、光影变化、镜头切接等动态信息。

适用场景：从零生成全新视频，白模只提供“动态骨架”。

公式：

```text
【参考声明】
+ 【对应关系映射】
+ 【剧情详述】
+ 【场景处理】
+ 【整体收束】
```

1. 参考声明：参考 `@视频1` 的运镜、动作、动线、光影变化、角色站位、音乐音效或画面节奏。
2. 对应关系映射：说明视频中的哪个颜色／形状模型对应哪张图中的哪个角色、道具或场景。
3. 剧情详述：按时间线或逻辑顺序详细描述动作、表情、台词和光影变化。
4. 场景处理：可用文字描述，也可引用背景场景图。
5. 整体收束：补充整体风格、画质、一致性约束、音频处理等。

特殊注意：如果白模有四肢或翅膀，要写出完整动作序列，否则容易动作僵化。官方建议粗颗粒度尽量不要上传带四肢或翅膀的模型。

### 7.2 细颗粒度

定义：建模完整、材质和结构清晰的 3D 模型视频。

重点参考：材质、风格、光影上色等直接渲染要求。

适用场景：模型和动作已经完整，只需要替换材质、光影或风格。

公式：

```text
【渲染指令】
+ 【分段渲染描述】
+ 【场景处理】
+ 【整体收束】
```

1. 渲染指令：将 `@视频1` 的白模动画渲染成最终成片。
2. 分段渲染描述：`0—N 秒` 的背景环境、色调氛围、人物材质和光影效果；写明转场触发点与方式；再写转场后的场景渲染。
3. 场景处理：可用文字或背景场景图。
4. 整体收束：说明新场景环境、人物渲染是否保持不变、音频处理等。

特殊注意：上传参考视频时，应去除轨迹线、坐标线、相机 cone 等干扰信息。

## 8. 从官方规范提炼的底层逻辑

以下是基于上述官方结构提炼出的 Skill 逻辑，不是额外的即梦官方语法：

### 8.1 先建立四层规格

```text
素材层：谁负责人物、动作、场景、音色
总述层：主体、地点、事件、风格、镜头方向
时间层：每段发生的画面、动作、镜头、声音和情绪意图
收束层：全片持续保持和全局禁止项
```

### 8.2 把静态事实、时间变化和全局限制分开

人物脸型、服装、场景和主体外观属于静态事实；动作、镜头、表情和声音属于时间变化；机位、画风、身份一致性和字幕／BGM 禁止项属于全局限制。不要把三种范围混在一句里。

### 8.3 每个动作都写“物理指令＋必要时的表达意图”

短视频主要写可观察的物理指令。长视频或情绪表演需要时，再补“潜台词／情感解析”，解释动作的叙事目的；潜台词不能替代画面动作，也不能变成要求生成字幕。

### 8.4 每次只选择当前任务需要的模块

基础短视频不自动加入 30 秒人物公式；人物任务不自动加入白模规则；视频编辑不自动套用图生视频动作模板。官方提供的是模块库，不是每个任务都要填写的固定长表格。

### 8.5 防错不是堆负面词

优先用素材映射、时间范围、作用对象、前后状态和保持项消除歧义；只有对当前失败有效的禁止项才加入。禁止项应和正向指令一致，不能一边要求表情不变、一边要求微笑变化。

## 9. 未核验能力边界

本文件核验的是官方手册中的提示词组织建议，不证明以下版本特定能力：

- 全能参考或多参考的上传数量上限；
- 首尾帧字段的具体语法和上传顺序是否始终固定；
- 权重语法、特殊 token 或 API 字段；
- 固定时长、分辨率、帧率和画幅限制；
- 纯绿幕是否能直接输出真正 Alpha 透明视频。

遇到这些问题，以当前界面和当前版本官方资料为准。纯绿幕属于生成层要求，不能等同于 Alpha 透明导出。
