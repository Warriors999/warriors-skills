# 参考证据到可检查的设计

## 最小参考记录

在当前项目保存简洁记录；仅问答时可在回答里提供，勿为简单任务制造文件负担。每个重要参考记录：

- ID、作者/机构、标题、原始页面或本地路径、查看日期、页码/节点/视频时间点。
- 角色：内容来源、主体素材、版式参考、风格参考、研究参考。
- 查看状态：完整查看、部分预览、仅检索候选、访问受阻。后两项不能作为视觉结论证据。
- 可见观察：结构、比例、层级、密度、色彩角色、字形、图表/流程语义、质感或运动。
- 可迁移规则、应拒绝的特征，以及目标中如何使用。
- 资产复用状态：仅研究、用户说明有权使用、已查看许可与用途条件、未知。用户持有文件不代表版权自动归属用户。

## 分析的精度

| 输入 | 可以确定什么 | 需要重新判断什么 |
|---|---|---|
| 可解析 PPTX / 设计源文件 | 对象几何、声明的字体/主题/字号、连接关系等可读取信息 | 实际字体替换、播放效果、视觉适用性、文件复用许可 |
| 截图/图片 | 可见层级、相对位置与比例、近似色彩、字形特征、遮挡 | 真实字体与字号、原始坐标、对象结构、可编辑性、动画 |
| 视频 | 已播放区间内的顺序、速度、触发线索、对象关系 | 未播放片段、实现技术、导出后是否仍可编辑 |

测量写 `observed`，截图估计写 `estimated`，为新内容设定写 `designed`，未看见写 `unknown`。截图取色会受压缩/显示影响；截图里的字高不能直接称作 24pt。精确重建需要已知页面尺寸与缩放，并仍要在目标环境复核。

## 迁移决策

先选一个主导的结构/字体体系，再组合互补素材和数据规则；避免同时拼接互相冲突的圆角、描边、投影和配色体系。用户指定结构时，明确对齐、遮挡、面积分配等不变量；可作必要适配并说明原因。

| 参考原则 | 目标实现 | 验收 |
|---|---|---|
| 结论先行、证据随后 | 按原文事实组织标题/图表/说明；来源独立记录 | 不添结论、数字或因果；阅读顺序清楚 |
| 网格与留白 | 按目标尺寸重建栏宽、边距、行距及文字安全区 | 长中文不溢出，密度接近目标，非仅封面相似 |
| 字形与色彩层级 | 定义标题/正文/注释字号、可用字体和色彩角色 | 字体实际可用，重点明确，屏幕/投影可读；9pt 不能当作会议正文推荐值 |
| 强调色具有语义 | 定义现状/目标、主流程/异常等颜色映射 | 单位、图例、对比和返回方向正确 |
| 温暖建筑或其他插画氛围 | 原创或授权的独立素材，保持比例并设置裁剪、安全区 | 主体无拉伸、不盖文字，位图内部编辑限制明确 |
| 递进讲述 | 把节点、线、注释分组并定义触发、顺序、时长 | 实际放映，保存重开后动画目标与先后仍正确 |

以上是方法示例，不是固定主题。原生模板适合且许可允许时可直接编辑；图片参考则需重建对象。研究不强制使用代码建页，也不保证自动获得设计师水平。

## 执行交接

交给后续技能的信息应包含：采用的参考 ID、规则与设计方向、固定字段、目标尺寸、字体与色彩角色、布局约束、所需素材及其权限、编辑/动效要求和验收项。

- 图片：提供中文提示词，按需含素材类型、主体、构图、背景、材质、灯光、色彩、逐字文字、固定条件和排除项；不向与任务无关的图像强塞 AI/科技风。文字、logo、参考主体等要求沿用用户规范。
- PPT：接到当前制作工具的主题/版式/对象或规格；重要文字、图表数值和流程标签保持原生，单独说明图片与特效的编辑层级。图片转对象属于重建路线，不能承诺所有内部细节可编辑。
- 网页：接到字体、间距、布局、断点和交互状态。
- 动效：接到对象分组、状态、触发及时间安排；网页动效不等于 PPTX 原生动画。

## 交付检查

### 协作交接

用户选择自己在 Figma/Sketch 精修时，将参考与设计建议落实为可接手的设计包，按请求提供：

这是用户主动选择的分工分支。默认由 AI 完成授权范围内能够完成的设计、精修和检查；操作繁琐或首次失败不能直接当作能力障碍，也不能用“后期你再修”替代应有质量。确实做不到时说明具体障碍并只交出最小剩余操作。

- 内容：逐页标题、正文、数字与流程节点的可复制文案；列明固定事实与待确认项。
- 参考：实际查看的具体内页、原作者来源及借鉴点；不只交网站清单。
- 效果图：展示结构、风格和材质的真实样张。允许探索稿为位图，明确其编辑层级；精确业务文字在文本稿另存。
- 独立素材：按需求单独交无业务文字背景、插画与特效。保持尺寸/裁切可用；要求透明时验证 alpha。图片中的复杂效果不能默认拆成可编辑图层，需从生成阶段规划部件。
- 规范：画布、色彩角色、字体与字级、网格/间距、投影建议；采用用户精修后的值。截图估计不冒充精确测量。

收到返稿后以用户最新精修稿为视觉基准、内容文档为事实基准；修改反馈对应区域，保留已定字体、位置和细节。涉及直接修改 Figma/Sketch 文件时，再读取对应技能并确认实际工具能力；研究交接不以 MCP 或额外订阅为前提。

效果图与素材交付可以是本次任务的终点。只有用户需要实际 PPT 时才进入组装与原生动画；整张图片可导入编辑器，不代表图片内部文字和效果已可编辑。流程逐步出现需在演示文件中保留独立对象；视频背景内部动效不等于 PPT 原生动画。

局部请求只交付本次对象。格式按编辑深度选择：PNG/JPG 背景用于裁切与替换；透明 PNG 用于独立摆放前景；SVG 适合简单矢量交换，但要检查导入后的路径、字体与效果。需改字时必须是目标编辑器的真实文本对象；需调投影时保留对象属性；需改图表数值时保留数据。可复制文案只作备份，不冒充完成排版的原生图层。

Figma、Sketch、PPTX 各自保留原生阶段源稿，优先在用户当前使用的一种设计工具精修，再按需进入演示。不要强制所有软件轮转，也不把导入成功视为无损往返。具体转换能力按当次文档、本机版本和代表页验证；不能通过更名扩展名伪造 .fig/.sketch/.pptx。原生制作接口未接通时明确说明当前可交的文件与待验证环节。

### 成品或阶段交付

对照参考逐项比：内容完整、层级与阅读路径、结构不变量、中文密度、图片比例、文字安全区、格式/尺寸、原生对象、目标环境和动画表现。先修正失败项再交付，并明确未验证的范围。几何脚本和包校验只能作为其中一部分，不能证明好看、好讲或已实现全部编辑联动。
