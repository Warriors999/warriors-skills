# PPT 协作设计

围绕用户本次任务交付高质量成果。用户可从任意环节进入并掌控目标、偏好和最终取舍。AI 完成授权范围内自己能够完成的工作，仅将确有能力障碍的最小部分交给人；不默认制作整套 PPT，也不默认把精修留给用户。

## 四道门

每个 PPT 任务都从第 0 门开始，包括新做、换风格、单页、返稿，以及只要背景或母版的任务。规范研究没有“可跳过”的版本；项目里已有规范卡时，做的是复核并写明沿用日期，不是跳过。

第 0、1 门是设计前的输入；第 2 门的确认门只适用于用户选择“先看图、确认后再制作”的路线。已授权原生制作、局部改字与批准方向内的返稿直接执行，不额外索取视觉确认。

### 0. 设计规范研究（所有场景，不限党政）

先查这个场景“什么算对”，再谈风格。找参考图不等于查规范，也不因为“这类 PPT 做过很多次”就免查。

- 所有场景都先查：党政/党建、国企事业单位、企业汇报、融资路演与上市披露、金融、医疗、学术答辩、教学培训、产品发布、数据汇报、展会大屏、英文国际会议。
- 受众、场地、屏幕比例、观看距离、时长、主讲方式。
- 分级记录：本任务适用的法律/监管/党内法规义务；主办方与用户明确要求；无障碍及设计建议。标准名称或权威来源不自动意味着对本次 PPT 强制适用，GB/T、公文格式及 WCAG 要说明边界。
- 设计建议：字体角色、字号、色彩面积、页边距、标题区、信息量、行距与字数。用户明确风格在不冲突于实际义务时优先。
- 先判断适用性与强制性，再比较证据。适用义务优先；用户/主办方要求其次；推荐标准与审美建议不能当作法律限制。
- 适用规定引用原文与条款；检索未找到时写“截至某日，本次检索未找到适用的专用标准”，记录范围和未知项，不推断标准不存在。
- 新场景完整研究；同项目局部修改只复核受影响项，记录来源、原证据日期、本次复核日期与沿用值；仍有效的证据无需重复联网。缺来源的建议可标暂定，不能伪称法规。遵守用户限定的检索范围，必要核对未完成时准确说明。

跨行业先查什么见 [场景规范索引](references/design-norms-index.md)；党政/党校场景读取 [党政党校场景](references/party-government.md)；研究方法与规范卡模板读取 [场景规范研究](references/design-research.md)。

### 1. 参考契约

用户给参考图时，先说明“参考什么、不参考什么、参考到什么程度”，再开始设计或生成。

- 标角色：内容来源 / 版式参考 / 风格参考 / 材质参考 / 研究参考。
- 遵守用户限定的视觉搜索范围；明确禁止任何外部检索时用现有依据复核，说明影响本任务的未核实项，不自行扩搜。
- 把参考拆成画布、区域比例、色板占比、字体气质、装饰几何、材质、光线、留白和禁止复制项。
- 形容词必须落地：每个“大气/山河/红绸”至少换成两个可检查参数。
- 一个属性只设一个主参考，不把多张图平均成“四不像”。
- 需要图像模型复现风格/材质时，把参考图作为参考输入，不只写文字描述；版式参考不直接拿去重绘，先拆几何再原生重建。

完整拆解表、权限话术、优先级和验收读取 [参考契约](references/reference-contract.md)。需要测量时运行：

```bash
python3 <skill-root>/scripts/slide-reference-audit.py audit 图片1.png 图片2.png --out ./reference-audit
```

### 2. 视觉稿与生产稿分开（含用户确认门）

用户要“先看图片效果，再要可编辑文件”时，默认走双稿制：

| 产物 | 用途 | 边界 |
|---|---|---|
| 视觉母版 | 给用户确认构图、气质、色彩、图像方向 | 优先用生产素材和真实原生排字合成预览；概念示意须标明 |
| 生产稿 | 用户确认后，改字、改数、加动画、交付 | 文字和关键形状为原生对象 |

**仅先图后稿路线按约定设置以下确认门：**

1. 方向确认：按约定做少量代表页，发给用户并停下，等明确确认（“可以”“确认”“就按这个”）。已有确认和批量授权继续有效，不重复询问。
2. 整套视觉确认：仅用户约定要看整套后再制作时设置。已授权“按这个批量做”“不用逐页确认”或明确要求转原生文件时按授权继续，不自行增加确认门。

任何一级未确认（未回复、只说“我看看”、提出修改），都停留在视觉稿阶段；改完重新确认。“没反对”不算确认。

预览前拆分背景、独立前景与原生文字/形状；可在内部用生产素材与原生排版合成看版预览，约定确认前不将其交为已批准的生产稿。确认后复用同一素材和排版参数。只有已有整页图且无干净素材可复用时才去字补全，不默认生成整套视觉图后再生整套去字底图。OCR 只用于定位，不用来定稿。

路线选择、WPS 能力边界、清洁底图要求、验收步骤读取 [先图后稿](references/image-first-production.md)。

### 3. 目标编辑器原生制作并验收

目标编辑器按用户指定与项目上下文确定，不固定为 WPS。制作前锁定共享设计契约：画布尺寸与比例、目标软件、字体/字阶、配色、网格、页码/标识、编辑深度、参考与锁定项。它约束所有执行技能，覆盖其默认尺寸、字体、页码徽章及装饰；未约定项再选合理默认值。通常交付 `.pptx`，其他格式核实对应路径；生产稿与预览分开。

“图片转PPT”不等于“文字可编辑”。先确认转换结果到底是什么：

- 普通多图导入：通常一图一页，文字仍是图片，不算可编辑（以实际输出为准）。
- WPS AI 图片转PPT：可能生成文本框，但复杂版式、图层、字体精度有限，先试 1 页。
- `editppt` / 手动重建：对象级控制最好，适合文字多、要求高的页面。

验收至少覆盖：内容逐字比对、对象是否为真文本、字体替换、实际文件渲染与视觉并排对照、目标编辑器打开/保存/重开、投影可读性。不能只凭“转换成功”或“包校验通过”交付。

## 核心责任

字体、换行、文本框、间距、对齐、圆角、投影、图层和组件等不按工种预留给人。工具和输入允许时由 AI 完成并检查，用户自愿亲自操作或明确只要参考/素材时遵守该分工。

“难、耗时、第一次失败、写了规范”都不是已证实做不到。先核实输入、工具与方法，在授权范围和既定预算内尝试合适的修复或替代执行路径；已有明确障碍时不为形式反复试错。不擅自购买、改供应商或降低质量要求。

确需人接手时，指出具体页面/对象、剩余操作、已核实的障碍、实际尝试及可用文件，仅交出受阻部分；其余可独立完成的工作继续。不能以“你可以精修”作为交付已知缺陷的理由，也不能把接口缺失说成整个设计任务都做不了。

## 先定位任务与交付

从当前会话和指定文件确定：本次对象与范围、最新主稿、保留项、目标软件、需要怎样编辑、实际交付物。信息已知就沿用，不让用户填写固定问卷。简单任务在心中明确即可；多人/多版本/跨软件任务写入已有项目记录，避免新建多份清单。

以当前输入检查真实执行能力，再承诺原生交付。把“已打开源文件”“已有类似样稿证据”“仅官方文档支持”“尚未验证”分开；发现关键接口或导出链路不通，应在大量生图或排版前说明，不能事后用 PNG/TXT 代替承诺的原生图层。

原生是硬要求且没有可行通道时，明确以“原生部分未完成”结束，列具体阻塞及已完成内容；只有用户接受替代交付后才按替代范围继续。完成状态按本次要求判断，原生接口缺口不能靠增加工作流文字宣称解决。

## 按需调用

| 请求 | 最小工作与交付 |
|---|---|
| 需求/逻辑/流程 | 梳理受众、目的、逐页信息、依据与主线/分支/返回；交付可用结构和文案 |
| PPT 实际制作（新做/换风格/单页/返稿） | 先新建或复核规范卡，有参考图时再出参考契约；按授权范围交付真实页面 |
| 找参考/定风格 | 用 `pinterest-reference-design` 找具体作品、提规则、推荐方向；到研究请求为止 |
| 背景/插画/特效 | 明确画布、文字安全区、独立部件与编辑深度；交付真实素材 |
| 单页/视觉样张 | 用该页真实信息量，沿用相邻页风格；按请求交样张或原生页面 |
| 局部修改/返稿 | 定位最新版和指定对象，只改授权范围，复核受影响内容 |
| 只要视觉图/母版 | 交付请求的视觉成果；仅约定先图后稿时等确认，不自行转原生稿或扩成整套 |
| 图片转可编辑 | 先判断文字/图层/动画需求，选 WPS、`editppt` 或手排；验收真对象 |
| 导出/组装/动画 | 选择最短转换路径，先验证一个代表对象/页面，再扩大 |

遵循 `visual-task-gate` 和 `warriors-work-principles`。规范研究对每个 PPT 任务都做：新场景新建规范卡，老项目复核旧卡并写明沿用日期，局部任务也不能跳过。视觉参考用现有稿做最小审计即可。不因提到 PPT 就自动生成整套，也不让一个背景任务经过所有技能。

选择当前可用的执行技能并读取它：图片沿用户规范与 OpenAI-Compatible Images 插件路由；视觉输入使用适用的 vision 能力；实际读写 PPTX 才加载对应演示技能。直接操作 Figma/Sketch 时确认接口并读取适用技能，不把接口存在当成本次已成功操作。动效区分原生点击序列与视频素材，按类型选工具。

**通用演示技能里的“每页必须有视觉元素”“正文 14–16pt”等建议只是模板经验，不是规范。** 以本任务的规范卡为准；党政/党校场景另见 [党政党校场景](references/party-government.md)。

## 设计与生产

需要从头探索时先推荐有区别的方向；方向已定就执行，不强制每次再选两三版。新风格先以少量代表素材/页面验证；批量沿用已定视觉锚点，避免逐页随机漂移。

语义、数字、单位、来源、主流程及异常逻辑优先核对；设计参考不能提供业务事实。效果样张可用位图，正式可编辑要求必须落实为目标软件对象。源文案与页面标签一一对应，局部改数同时检查关联结论和图形。

图像生成只负责它擅长的部分：背景、材质、插画、照片、复杂视觉。中文标题、正文、引文、页码和简单几何优先原生，并以同一素材与排版合成预览；用户明确要求模型整页概念稿时标为示意并说明后续重建成本，不默认扩成整套。没有语义关系的山河、长城、红绸、光效不因“党建风”自动加入。

涉及修改、批量素材或跨软件交接，读取 [生产与返稿](references/production-and-revisions.md)。需要可编辑/动画或文件转换，读取 [交接约定](references/handoff.md) 和 [先图后稿](references/image-first-production.md)。这些文件包含素材拆分、主稿冲突、长文冲突和格式降级的处理规则。

## 验收与结束

质量以内容准确、规范适配、参考适配、视觉层级、字体与版式细节、素材质量、编辑能力及实际使用为准。AI 应主动发现和修复自己可处理的缺陷，不能只做到可生成、可导入或包校验通过就交给用户收尾。最终不足和未完成项如实报告，质量目标不能冒充已达到的结果。

仅先图后稿路线检查约定的视觉确认是否完成；已获批方向内的修改、原生制作与批量工作按现有授权继续。初次检查即满足标准可以通过，不为流程制造缺陷。

按本次请求检查实际文件及视觉：

1. 尺寸、比例、边距、文字安全区；
2. 内容、引文、数字、页面标签逐项对应；
3. 参考图的区域比例、色板占比、材质语言是否一致；
4. 文字是否仍为文本、图片/形状是否独立、字体是否被替换；
5. 视觉并排对照是否有结构偏移、裁切、遮挡、颜色漂移；
6. 目标编辑器打开/保存/重开，按用途检查放映、动画初始状态和点击顺序。

分别记录：结构检查（包/关系/文字/对象）→ 清单模拟预览（布局推测）→ 实际 PPTX 经演示引擎渲染（真实字体/换行/排版）→ 目标编辑器保存重开（兼容性）→ 放映（播放/点击）。各层不能互相替代；Pillow 按清单另画不算 PPTX 渲染。视觉交付必须检查真实文件渲染，缺少时标“视觉验证未完成”，不能称视觉验收通过；目标软件或放映未测也单列未知。纯素材直接检查实际素材，不要求创建 PPTX。需要像素对照时运行：

```bash
python3 <skill-root>/scripts/slide-reference-audit.py compare 视觉母版.png 渲染页.png --out ./qa
```

交付实际文件/预览和最必要的使用说明；原稿、素材、视觉母版、生产稿清晰区分。说明本次改了哪里、保留什么、是否有未完成项。用户要提示词时给提示词，用户要素材或页面时交真实产物。完成本次范围即停止，不自动扩成全套、安装更多工具或转去其他服务。

结构文案与显式字体检查可用 `python3 <skill-root>/scripts/pptx-content-audit.py 生产稿.pptx --expected-text 源文案.json --output ./qa/content.json`。源文案为 `{"slides":[{"text":"该页准确文字"}]}` 或 `{"slides":["该页准确文字"]}`，标点、空白与段落顺序须一致。字体清单不能证明已安装或实际显示正确，继承字体未解析时记为未知。图像对照检查原始尺寸与比例；同纵横比的分辨率归一化须显式加 `--normalize-resolution`，不拉伸隐藏比例错误。
