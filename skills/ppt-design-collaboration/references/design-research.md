# 场景规范研究

这份文件解决一件事：在做版式之前，先知道这个场景“什么算对”。找参考图不能代替查规范；用户给了参考图，也不等于场景规范已经清楚。

## 适用范围：每个 PPT 任务

规范研究是固定第一步，不是“新做/换风格”才做，也不只针对党政。以下情况都从这一步开始：

- 新做、换风格、换行业、换受众。
- 单页、局部返稿、只要背景或视觉母版。
- 用户给了参考图、模板或旧稿。
- 用户问“一般用什么字体/字号/版式”，或对上一版只说“不对、太土、太花”。

新场景完整研究；局部修改只复核受影响项。已有规范卡时记录来源与原证据日期、本次复核日期、变化项及沿用值；来源仍适用无需重复外搜。无来源的设计建议可标暂定，不可冒称法规；缺失的适用义务证据记为未知。小任务沿用现有记录，不额外建立复杂文档。

## 两条研究轨道

| 轨道 | 解决什么 | 何时做 | 用户给参考图时 |
|---|---|---|---|
| A. 场景规范 | 受众、场地、政治/行业底线、字体字号、色彩角色、信息密度 | 所有 PPT 任务必做 | 继续做，参考图不能替代 |
| B. 视觉参考 | 构图、版式、材质、光线、装饰语言 | 用户参考优先；不足时补搜 | 先拆用户参考，再决定是否补搜 |

用户说“不再找参考”即停止 B 的扩展搜索。明确禁止所有外部检索时，A 使用已有证据复核，说明本次相关的未核实项；不擅自扩大检索。

各行业先查哪些文件、哪些是硬规范、哪些只是经验值，见 [场景规范索引](design-norms-index.md)。

## 来源等级

从高到低取证据，低等级来源不能推翻高等级：

1. 法律法规、国家标准、党内法规、主办单位正式 VI/模板。
2. 主办单位官网、正式文件、公开课纲、场地技术参数。
3. 行业权威机构、专业出版社、设计系统官方文档。
4. 设计工作室案例、完整作品集、公开演示稿。
5. 模板站、自媒体教程、搜索摘要（只作线索，不作结论）。

先判断来源是否适用于本次用途及是否具有强制性。规范卡分为“适用法律/监管/党内法规义务”“主办方或用户要求”“无障碍/设计建议”；国家标准、正式模板和 WCAG 不应混为普遍法律义务。检索未找到时写“截至某日，本次检索未找到适用的专用标准”，记录范围与未知项，不断言不存在。

## 检索方法

先按“场景 + 交付物 + 约束”搜，不按形容词搜：

- `党政机关公文格式 GB/T 9704 字体 字号`
- `党课 PPT 字体 字号 排版`
- `党建 PPT 设计 注意事项 党徽`
- `[主办单位] VI 手册 演示模板`
- `projection slide minimum font size contrast`
- `assertion evidence slides`

打开原始页面或正式文件，记录真实看到的条款/页面。搜索摘要、模板缩略图和“看起来像”不能算研究完成。

## 规范卡

研究后写一张短卡，放在项目记录或回复里。没有的项目写“未确认”，不要留空装作已定。

```md
场景规范卡
- 场景/受众：
- 使用场地与屏幕：比例、尺寸、观看距离、亮度
- 时长与讲述方式：主讲人、翻页节奏、是否投影
- 必须保留：主办方 VI、标题格式、署名、日期、党徽/标识
- 禁止项：政治表述、商业元素、错误徽标、无关装饰
- 字体角色：标题 / 正文 / 引文 / 数字 / 注释
- 字号层级：封面 / 章节 / 页标题 / 正文 / 注释（写明画布）
- 色彩角色：主色 / 辅色 / 强调 / 底色及面积比例
- 版式：页边距、标题区、正文区、每页信息量、行距、每行字数
- 内容核对：引文来源、姓名职务、会议全称、数字单位
- 参考图权限：（见 reference-contract.md）
- 适用义务及条款：
- 主办方/用户明确要求：
- 设计/无障碍建议（注明经验值）：
- 来源、证据日期、本次复核日期及沿用范围：
- 未确认项：
```

## 党政/党校场景

截至本卡所记录的检索日期与范围，如未找到党课 PPT 专用标准，应如实写“本次未检索到”，不作不存在的断言。《中国共产党党徽党旗条例》用于相应用途的标识规范；主办单位 VI 属于项目要求；GB/T 9704-2012 的公文字体调性仅作参考。字号、留白、色彩面积和每页字数属于投影设计建议，结合场地与用户风格调整。

具体字号、色彩和验收项见 [党政党校场景](party-government.md)。

## 研究结果怎么给用户

用 3–6 条说清，不贴一堆链接：

- 这个场景的硬底线是什么；
- 本次采用的字体/字号/色彩/密度；
- 哪些来自规范，哪些是经验值；
- 用户参考图负责哪一部分；
- 还有什么需要主办方确认。

示例：

> 本次按党校课件处理：标题用宋体调性，正文用黑体，投影正文不低于 24pt；默认建议红色约 30% 以内，用户要求明亮红金或红底时按其方向重新检查可读性，党徽使用官方素材不重绘。GB/T 9704 只管公文，不直接规定 PPT 字号，所以字号按 16:9 大屏经验值给。图片1 只作为版式与配色参考，不替代这些规范。

非党政场景同样先给规范，只是依据换成对应行业的：

> 本次按上市公司年度业绩汇报处理：先按公司 IR 模板和已披露口径核对数据，遵循《上市公司信息披露管理办法》的真实、准确、完整要求，加入风险提示，不做无依据预测；图表统一品牌色阶并标注来源；字号按会场投影经验值给，正文不低于 20pt。参考图只负责版式与配色。

> 本次按高校学术答辩处理：按学院模板和盲审要求检查匿名信息、页数与时长；参考文献用 GB/T 7714-2015，标点和数字用法按 GB/T 15834、GB/T 15835；图表标注数据来源。字号按答辩教室投影调整，不套用党政或商业模板。

## 常见错误

- 把“找参考图”当成“做规范研究”。
- 用户发了参考图，就默认规范已经确定。
- 只在党政场景查规范，企业汇报、学术答辩、内部培训就跳过。
- 用上次的规范卡但不复核来源、场景和日期。
- 只写“庄重、大气、高级”，没有字号、色值、面积和版式。
- 把模板站的排版当权威标准。
- 把公文标准直接套成 PPT 标准，不说明适用边界。

## 可选的进阶做法

这些不是每次必做，按任务复杂度选用：

| 做法 | 解决什么 | 落到哪里 |
|---|---|---|
| 设计令牌（design tokens） | 颜色、字号、间距、圆角在多页/多轮生成中漂移 | 先写一张 token 表，提示词和 PPT 共用同一组值 |
| 风格样片（style tile） | 只看整页图，难以判断字体/色块/材质是否成系统 | 一页放色板、字阶、装饰母题、图像处理方式，先确认再批量 |
| 断言—证据（Assertion–Evidence） | 标题只写主题，页面没有观点 | 标题写成一句判断，视觉承担证据；需用户允许改文案 |
| 视觉回归（visual regression） | 转换/重排后结构悄悄跑偏 | 渲染成 PNG，与确认图并排 + 分区像素差 |
| 文字安全区蒙版 | 装饰压字、标题贴边 | 在母版上画 5%/10% 安全区，生成和验收都对照 |
| 对比度检查 | 红底白字、金底白字投影发虚 | 正文 ≥4.5:1，大字 ≥3:1 |

上述对比度是辅助可读性的建议，WCAG 本身不自动成为所有 PPT 的法律义务；适用无障碍法规、合同或主办方要求采用时，注明范围与版本。投影还须检查现场亮度。

参考依据：W3C WCAG 2.1 Contrast (Minimum)；W3C Design Tokens Community Group；Michael Alley 的 Assertion–Evidence 方法。它们提供方法，不替代主办方规范。
